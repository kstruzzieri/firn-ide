The rules, exit criteria and release steps are in [README.md](README.md).
They and this contract were written after the freeze, so `release/v0.13.0` and
the v0.13.0 tag do not carry them. They live on `develop` and reach `main` with
v0.14.0, whose release branch is cut from `develop`.

**Theme:** everything `develop` holds since v0.12.0, and nothing new: the
narrow-pane redesign of the Golem configuration workspace with named profiles,
visible outcomes for every Golem chat run, and protection for state files Firn
could not read.

**Exceptions to the README, agreed 2026-09-25:** the soak is four days rather
than seven, because the train starts mid-cycle; and #359 and #360 enter after
the freeze under the data-loss exception. By amendment on 2026-09-26, #372
enters after the freeze as a security exception, and by amendment on
2026-10-01, #391 enters under the regression exception.

## Known issues

Each ships in v0.13.0 as it did in v0.12.0:

- #361: New chat clears only the view, so the model still receives the cleared
  turns. A long session in one workspace can fail repeatedly at the 2 MiB
  session limit, and only a restart clears it. Target v0.14.0.
- #314: screen readers may not announce some Golem configuration status
  messages (the grant notice, the Refresh busy notice, the result of an Apply,
  the route editor's model match count). Target v0.14.0.
- #316: the declared macOS 12.0 floor is too low. The app uses web APIs that
  need Safari 15.4 (macOS 12.3), and its build targets Safari 16. Target
  v0.14.0.
- #355: the destination approval row names one model where the approval covers
  the whole endpoint, and hides the fallback path. Target v0.15.0.

Two arrive with #359's fix. In v0.12.0 an unreadable file was silently
overwritten; in v0.13.0 it is kept, but the panel says too little:

- #366: when `.firn/run-profiles.json` cannot be loaded, the Run Profiles panel
  gives no notice until a change is refused. Not yet scheduled.
- #367: picking up the fixed file needs a restart of Firn, or reopening the
  folder after opening another. Not yet scheduled.

## Exit criteria

The criteria in [README.md](README.md), with two notes:

- The VoiceOver pass and the packaged-app check pass when nothing regressed
  against v0.12.0. The known issues above are not failures.
- If Backend Tests fails, read the log. A timeout in
  `TestExecutorPhase2B_DrainInvalidatesAndWaitsForExactRestartReservation` is
  the known flake #351 and needs a successful rerun; any other failure is a
  real failure.
