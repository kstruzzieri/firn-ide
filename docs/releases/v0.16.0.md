The rules, exit criteria and release steps are in [README.md](README.md).
The milestone mirrors In and Stretch, including the v0.15.0 items that rolled
at that release's freeze on 2026-11-04.

**Theme:** one Golem model. A user adds a provider from a preset and picks the
model Golem answers with in one step, every commit message comes from that
model and no other, and Apply asks about a change only when the change can
narrow what a use case receives. This
is the first slice of the Golem model discovery design as the issues #490 to
#503 record it, the slice that cites go-llm v0.5.0 APIs only.

### Schedule

- **Wed 2026-11-18, Stretch stops.** Stretch work starts only once In has merged.
  This departs from the README, which lets Stretch merge up to the freeze, so
  that the release-candidate pass covers everything that ships.
- **Thu 2026-11-19, release-candidate pass** on a packaged build of `develop`,
  with Fri 2026-11-20 and Mon 2026-11-23 held for its fixes.
- **Fri 2026-11-20:** v0.17.0's contract is drafted.
- **If In is late, the dates move.** When In has not merged in time for the
  release-candidate pass, the pass, the Stretch stop, the freeze and the release
  move together by amendment, decided as late as the work allows. The release
  stays at least seven days after the freeze and waits until all exit criteria
  pass.

## Stretch

Ships only if it merges to `develop` by the stop date under Schedule.

Work starts in this order once In has merged. The list is more than this train
has room for, so only its head is likely to ship.

1. #506, re-scoped. A model with no context window runs Golem chat on go-llm's
   8192-token default input budget, and the Declare form has no field to set
   one. Add an optional field, where a blank means omitted, and a visible line
   wherever the window is unset. A declared name joining a selector with a
   different window is refused, so the form handles that conflict. A model
   already in the file stays a hand edit, and the line says so. Its original
   refusal ends with #491. M by estimate.
2. #397 and #442: the run-profile store overwrites a file that changed on disk,
   or a run-recency sidecar it could not read. A branch checkout followed by a
   Save is enough to trigger #397. Git can recover a committed version; an
   uncommitted external change is lost. Both are fixed by latching writes in the
   same store.
3. #510: on macOS and Linux, Resolve can write one file's draft over another when
   `a/b` and `a\b` hold a file of the same name. It needs two folders that differ
   only by a slash and a backslash, and it has not been reproduced in the app.
4. #511: a repository folder whose name ends in a space loses it, so commit
   message generation fails. A regression, for generation.
5. #512: a staged join shows a false Incompatible on an unchanged route sharing
   the model. A regression, and it would sit beside #493's real row warnings.
6. #521 and #522, in one pull request tested natively: deleting or renaming the
   file at the file tree's active row from outside the tree jumps the tree to its
   top; focus stays on the page when a refresh restores the tree unchanged; two
   of the tree's focus guards have no test holding them.
7. #515: generating a commit message drops keyboard focus to the page.
8. #513: the Git panel blames Golem's file access rules for a staged file outside
   the open folder. After #491, which changes the same flow.

All of these ship in v0.15.0 as known issues, and its Known issues say what was
run and what was only read from the source. #506's new scope comes from this
amendment. Unranked, after those:
